Resumable execution state

Kill the scan. Resume it. Nothing re-billed.

The national scan screens ~1,800 sites against a paid API — so it checkpoints every completed site to a JSONL file as it lands. Interrupt it at row 1,500 and it continues from 1,501; a different process, a different day, even a different model can pick it up from that one state handle. This runs the same mechanism live, five sites at a time, against a throwaway demo checkpoint. Watch the state grow.

This demo runs against a throwaway demo-checkpoint.jsonl, never the real scan's checkpoint. The resume batch is capped server-side at 5 sites, so it can't trigger a full paid run. This is the "stateful continuity" primitive: the checkpoint is the state handle; the execution is resumable even though each screen is a stateless call.
